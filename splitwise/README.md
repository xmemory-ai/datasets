# The Splitwise dataset

This dataset mirrors a **small internal micro-product** we built at xmemory. The product is inspired by **Splitwise**, the app many of us use for casual group expenses (lunches, trips, and the like).

Internally we call the micro-product **“Friendly Expenses”**. For this release we keep the dataset under the name people will recognize: **the Splitwise dataset**—a nod to the app that inspired the scenario.

## What the data represents

The core artifact is a **ledger**: a fixed circle of friends goes out **together or in sub-groups**, and **one person pays the bill** each time. The natural **read** task is to infer **who owes whom how much** after a sequence of expenses.

### Example (intuition)

Imagine **Alice**, **Bob**, and **Charlie** share **sushi for \$150**; **Bob** pays. Later **Alice** and **Bob** have **coffee for \$50**; **Alice** pays.

- From sushi: Alice and Charlie each owe Bob **\$50** (their even shares of the \$150 tab Bob advanced).
- From coffee: Bob owes Alice **\$25** (his half of the \$50 Alice advanced).

If the three **settle the shared pot in one go**, you might summarize it as: **Alice** still owes **\$25** net into the pot, **Charlie** owes **\$50** from sushi, and **Bob** collects **\$75**—the arithmetic should close.

That split is illustrative; the released bundles use richer, autogenerated outings and questions, but the **idea** is the same: **writes** are journaled expenses; **reads** are balance-style questions about individuals.

## Autogeneration and code

Because the dataset is **autogenerated**, we ship not only the **data** but also the **code** used to produce more of it (under `code/`). That makes it easier to vary seeds, group sizes, and phrasing—useful for **reducing overfitting** and probing **model inconsistency** across runs.

## Layout in this repo

| Path | Role |
|------|------|
| `benchmarks/` | Generated benchmark bundles in our YAML layout |
| `code/` | Pipeline to synthesize outings, build eval fixtures, and export bundles |

Each bundle under `benchmarks/` follows the repo-wide **benchmark → dataset → inputs** layout (see the top-level `README.md`). Concretely:

```text
benchmarks/
├── splitwise_benchmark_001.yml          # benchmark
├── splitwise_benchmark_001/             # dataset
│   ├── dataset.yml
│   └── inputs/data.yml
├── splitwise_benchmark_002.yml
├── splitwise_benchmark_002/
│   └── …
└── …
```

See `code/README.md` for how to run the generators locally.
